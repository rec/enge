Dexed Mk I constant-gain core comparison¶

Measured on 2026-11-04 against Dexed revision fea2f0f0f2c397799f59b27eb11c038cd34b22c5. The enge renderer includes the approved explicit feedback endpoints and quarter-strength rule for algorithms 4, 6 and 32. Its enge/yamaha.py SHA-256 is 4f9d45516a947cb926fc76f8ba3b9f291094dcad386cc7ac745741b28692d6bc. The reference uses the actual Mk I core, including its integer sine/amplitude lookups, feedback shifts and two- and three-operator kernels.

Method¶

The standalone harness renders 750 blocks of 64 samples, exactly one second at 48 kHz. Algorithms 3, 4, 5, 6, 31 and 32 each run at feedback 0, 1, 4 and 7 with constant, equal operator gains of 0.03125, 0.25 and 1: 72 cases in the complete CSV.

For every operator, the Q24 frequency increment is exactly 153791 and the initial phase is zero. level_in is L * 2**24 for L in 9, 12 and 14; gain_out starts at (16 - L) * 1024 to avoid an initial block gain ramp. This corresponds to continuous gain 2**(L - 14). Feedback history starts at zero. Each raw signed 32-bit reference output is divided by 2**24 before comparison.

The enge comparison constructs an unpacked DX7 voice with the same algorithm and feedback; all operators use ratio mode, coarse 1, fine 0 and neutral detune 7. Oscillator sync is on, transpose is neutral, and pitch-envelope levels are 50. LFO depths and sensitivities are zero. Explicit pitch_hz is 153791 * 48000 / 2**24. A public note snapshot sets every amplitude envelope's level to L * 2**24, stage to 3 and held to true before restoring and rendering 48,000 frames. Thus there is no amplitude ramp, pitch drift, release or LFO variation in either stream. The remaining differences are within core execution; this experiment does not determine whether they all follow from quantization.

Relative RMS is norm(enge - reference) / norm(reference) over all 48,000 frames. The CSV also records maximum absolute error and each stream's RMS before any WAV scaling. Retained WAV pairs use one common divisor per pair, recorded in the CSV, and round to signed 32-bit PCM using round(sample / divisor * (2**31 - 1)). No independent level fitting or time alignment is applied.

The two multi-operator loops still fail reference qualification at the high-gain setting. Their similar overall RMS values do not establish waveform agreement. The large differences persist after removing envelope timing, block gain ramps and pitch drift. At gain 0.25, maximum-feedback errors for algorithms 4 and 6 are 0.2329% and 0.2990% respectively. These observations are consistent with feedback sensitivity to arithmetic differences, but do not prove that explanation or exclude a core-model error. Integer arithmetic isolation remains required.

This is a controlled FM-core comparison, not a complete named-patch comparison, DAC model, native callback qualification or hardware validation. The reference's hardware accuracy is not established by agreement with it. These results do not replace the earlier MSFA patch/envelope comparisons, which exercise other paths.

One-bit phase sensitivity control¶

The reference-only control runs the same Mk I core twice, changing only OP6's initial phase from zero to one Q24 least-significant bit: 2**-24 cycles. At maximum feedback and unit operator gain:

Algorithm Relative RMS difference First differing frame Perturbed reference WAV
4 19.9127% 1729 one phase bit
6 2.2912% 705 one phase bit
32 0.0006941% 2753 one phase bit

These recordings use the same divisors as their unperturbed Mk I recordings above. At gain 0.03125, the one-bit perturbation produces identical output in all three cases; at gain 0.25 all relative differences remain below 0.0021%. Thus the high-gain loops amplify a tiny initial-state difference even with identical arithmetic. This demonstrates sensitivity, but does not fully explain the larger enge differences or prove that enge's core is otherwise correct.

Reproduction¶

Download source/engine/EngineMkI.cpp and .h, plus source/msfa/ files synth.h, aligned_buf.h, fm_op_kernel.h, fm_op_kernel.cc, controllers.h, fm_core.h, fm_core.cc, sin.h, sin.cc, exp2.h and exp2.cc from the pinned revision. Place the engine files in a temporary directory and the others in its msfa subdirectory. In that temporary controllers.h only, omit the unused #include "../debugger/Logger.h" to avoid pulling in the JUCE application logger. No DSP code is changed. Set DEXED_CORE to that directory and compile:

c++ -std=c++17 -O2 -fwrapv -I"$DEXED_CORE" render-dexed-mki.cc \
  "$DEXED_CORE/EngineMkI.cpp" "$DEXED_CORE/msfa/fm_core.cc" \
  "$DEXED_CORE/msfa/fm_op_kernel.cc" "$DEXED_CORE/msfa/sin.cc" \
  "$DEXED_CORE/msfa/exp2.cc" -o /tmp/render-dexed-mki
/tmp/render-dexed-mki 4 7 14 0 /tmp/mki-alg4.i32
/tmp/render-dexed-mki 4 7 14 1 /tmp/mki-alg4-phase-lsb.i32

-fwrapv specifies the signed integer wrap used by the reference phase accumulators. The output is 48,000 native-endian signed 32-bit samples; this run used little-endian macOS. The harness was also checked with -Wall -Wextra -Werror -Wno-unused-parameter -fsyntax-only. Reference source licenses remain with Dexed; the repository contains the harness and generated measurements, not copied reference DSP source.

Integer-kernel graph isolation¶

The graph-isolation harness executes the exported uFor topology data using the pinned Mk I mkiSin function, then compares it with Mk I's own algorithm dispatcher and feedback kernels. It includes EngineMkI.cpp directly to reuse that exact integer kernel; there is no independently implemented sine or gain lookup in this control. The graph data comes from uFor revision 829ba12dbc926489101aa5376a10a5e0803c3914. Each row contains algorithm number, feedback source/destination, carrier count and carrier numbers, followed by edge count and source/destination pairs.

All 32 algorithms run at feedback 0, 1, 4 and 7 with four profiles:

Profile Constant log levels Q24 increments Initial Q24 phases
0 all 9 all 153791 all zero
1 all 12 all 153791 all zero
2 all 14 all 153791 all zero
3 OP1 through OP6: 9 through 14 153791 * operator_number 123456 * (operator_number - 1)

The asymmetric profile separates operator order, gain and frequency. Every case renders 48,000 frames. Graph execution sums the exported modulation edges, reads the two preceding samples from the feedback source, shifts their sum into the feedback destination with the approved strength rule, and sums the exported carriers. All operators in these DX7 graphs have feed-forward edges toward lower operator numbers, so descending operator order is valid. Each case resets phases, operator gains and both feedback histories. No amplitude envelopes are advanced.

All 512 cases agree exactly: zero mismatches across 24,576,000 integer samples. The complete CSV records mismatch count, maximum absolute Q24 error and relative RMS error for each case. The retained unit-gain, feedback-7 graph WAVs are byte-identical to the corresponding Mk I WAVs above: algorithm 4, algorithm 6 and algorithm 32.

This establishes agreement of the exported graph, operator ordering, carrier sum and feedback scheduling with the pinned dispatcher under these fixed-gain conditions. It does not establish an independent implementation of the integer kernel, dynamic-gain behavior, the production floating renderer's equivalence, complete patch rendering or hardware accuracy. It supports replacing the floating core as the next model decision, rather than another topology change.

Build with the same temporary reference source directory described above. Since the harness includes EngineMkI.cpp, do not also list that file as a separate translation unit:

c++ -std=c++17 -O2 -fwrapv -I"$DEXED_CORE" compare-dexed-mki-graph.cc \
  "$DEXED_CORE/msfa/fm_core.cc" "$DEXED_CORE/msfa/fm_op_kernel.cc" \
  "$DEXED_CORE/msfa/sin.cc" "$DEXED_CORE/msfa/exp2.cc" \
  -o /tmp/compare-dexed-mki-graph
/tmp/compare-dexed-mki-graph dx7-feedback-graphs.txt /tmp > /tmp/mki-graph.csv

The output directory must exist. The harness also writes graph-4.i32, graph-6.i32 and graph-32.i32 there; convert them to WAV using the matching wav_divisor values in dexed-mki-core.csv, as in the original comparison.
