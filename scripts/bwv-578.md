# Bach benchmark source and rendering

`bwv-578.mid` is an adaptation of Johann Sebastian Bach's Little Fugue in G
minor, BWV 578, transcribed by **Frank Nordberg / musicaviva.com**, distributed
through the Werner Icking Music Collection and IMSLP.

## Adaptation

Notes, velocities, note-on/off ticks, tempo, meter, and key signature are
unchanged. The source uses 480 ticks per quarter note, a quarter-note tempo of
869565 microseconds, and lasts 239.99994 seconds. Its four note tracks remain
separate. Channels below are MIDI's human-facing 1-based channel numbers;
the Python mapping uses 0–3.

| Part | Original channel | Stored channel | Notes | Engine |
| --- | --- | --- | --- | --- |
| Bass | 4 | 1 | 179 | FM, ratio 1, index 0.65 |
| Tenor | 3 | 2 | 511 | Triangle oscillator |
| Alto | 2 | 3 | 268 | Looped harmonic sample |
| Soprano | 1 | 4 | 807 | FM, ratio 2, index 0.85 |

Tracks are named for their parts. Every half beat, three channel messages are
inserted before existing events at that tick. For beat position `b` and stored
zero-based channel `c`, values are rounded to the nearest integer:

```
CC11 expression = 108 + 5*sin(2*pi*b/32 + c*pi/3)
CC1 timbre      = 64 + 8*sin(2*pi*b/24 + c*pi/2)
pitch wheel     = (3/200)*8192*sin(2*pi*b/8 + c*pi/4)
```

The patches interpret pitch wheel as ±200 cents, giving roughly ±3 cents of
movement here. Expression varies from 103 to 113 out of 127. CC1 slightly changes
FM index or oscillator/sample filter cutoff. The renderer smooths these controls
over 100ms. Original velocities scale amplitude per trigger. Programs in the
source are retained as metadata for other MIDI players but overridden by the
explicit enge patches. The soprano enters first, followed by alto, tenor, bass;
four engines do not imply four voices are sounding from frame zero.

The alto source is a deterministic one-second, 220Hz sample with second/third
harmonics of 0.25/0.12, divided by 1.37. Its integer cycle count permits continuous
looping through release. It is synthesized once during preparation, then played
by the sampler with pitch tracking and interpolation. No sample pack is needed.

## Running and measuring

From the repository root:

```
uv run python scripts/bach.py
uv run python scripts/bach.py --block-size 997 --output /tmp/bwv-578-997.flac
uv run python scripts/bach.py --backend native --output /tmp/bwv-578-native.flac
```

The default is entirely NumPy. `--backend native` selects Rust for all four parts.
Compare like configurations when benchmarking. The default output is `bwv-578.flac` in the working directory,
48 kHz stereo, lossless 24-bit PCM, with 250ms added for release and final silence.
The generated FLAC is ignored by Git; the MIDI is tracked.

The script reports audio duration, notes, peak, and elapsed time including
preparation, rendering, and encoding. It prints progress every ten audio seconds.
Run on an otherwise idle machine for useful timing comparisons. Rendering uses
bounded audio blocks and a temporary WAV, then atomically publishes the FLAC.
It requires the existing `flac` command. There is no normalization, limiter, or
reverb; exceeding PCM headroom raises an error and preserves any previous output.

The MIDI adapter supports synchronous PPQN files, exact tempo accumulation,
notes, CC1, CC11, and pitch wheel. Absolute times are rounded to the nearest
output frame, ties to even. Simultaneous events preserve merged track order;
repeated same-key notes match releases FIFO. Unsupported controllers, unpaired
notes, asynchronous files, and SMPTE division fail explicitly.

The full performance is an opt-in benchmark, not part of every unit-test run.
Tests check the stored parts/modulation ranges and exercise a short four-engine
performance, including release silence, block invariance, and FLAC PCM round-trip.
